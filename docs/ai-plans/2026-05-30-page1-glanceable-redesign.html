Page 1 Glanceable Redesign Plan

Goal: make Page 1 feel like a calm home overview where the active or next calendar event is the most important element, while calendar navigation, weather, transport, and diagnostics remain useful.

Current Behavior

  • Page 1 uses a two-column layout: calendar panel on the left and schedule/transport panel on the right.
  • Calendar events are rendered as equally weighted lines inside events_scroll.
  • The current event can get a subtle background highlight, or a red line can be placed between events.
  • The selected calendar date stays selected until the user taps another date, taps Сегодня, or the UI reloads.
  • Transport is displayed as a separate block below the event list.
  • The simulator now exists, so Page 1 layout changes can be checked before flashing hardware.

Desired Behavior

  • The active event, if one is happening now, becomes the hero element.
  • If no event is active, the next upcoming event becomes the hero element.
  • All-day events remain visible, but they do not outrank active or upcoming timed events.
  • If the selected date is not today, the first event for that selected day becomes the hero element and the UI clearly shows that this is a temporary date view.
  • Remaining events become a quieter compact list under the hero block.
  • The calendar remains visible and interactive, but it should not visually overpower the nearest-event summary.
  • After choosing a non-today date, Page 1 automatically returns to today after an idle timeout.
  • The redesign should stay within Page 1 and avoid changes to Bridge API contracts.

Recommended Layout

  • Keep the existing top bar height and left/right page split to minimize risk.
  • Right panel top:
    • small status label: Сейчас, Следующее, or Выбранный день;
    • large event title, using the existing Cyrillic 24px font or the 32px built-in font only if text still fits cleanly;
    • time range and relative cue, for example 18:30-19:30 · через 42 мин or до 19:30.
  • Right panel middle: compact list of the next 3-5 events, excluding the hero event.
  • Right panel bottom: compact transport summary, still two directions but visually quieter than the hero event.
  • Left panel: keep the calendar, but tone down ordinary dates and make today/selected date clearer if LVGL calendar styling allows it without brittle hacks.
  • Top bar: keep weather compact; avoid introducing a new large weather card in this pass.

Calendar Auto-Return

  • When the user taps a non-today date, record the interaction timestamp with esp_timer_get_time().
  • Use an idle timeout of 5 minutes by default.
  • The existing time timer can check whether the selected date is non-today and whether the timeout elapsed.
  • On timeout, set selected date back to today and call request_calendar_date(today).
  • Do not change the active tile/page when auto-return happens.
  • Manual Сегодня should clear the pending timeout immediately.
  • Keep the auto-return quiet: no countdown label in the first implementation. The visible Сегодня button and selected-day title are enough.

Implementation Plan

  1. Add Page 1 UI references for the hero event block: status label, title label, time label, and optional empty-state label.
  2. Replace the current equal-weight event list positioning with a hero area plus compact list area.
  3. Refactor calendar rendering logic to choose a hero event:
    • prefer active timed event for today;
    • otherwise choose next timed event for today;
    • otherwise use an all-day event only when there is no active or upcoming timed event;
    • otherwise choose the first timed event for selected non-today date, with all-day as fallback;
    • fallback to a calm empty state if no events exist.
  4. Render compact events below the hero, excluding the hero item when possible.
  5. Keep existing calendar fetch flow: UI calls request_calendar_date, network task calls bridge_fetch_calendar, UI timer reads bridge_get_calendar_data.
  6. Add the 5-minute selected-date auto-return logic.
  7. Update simulator fixtures if needed so one event is active or upcoming enough to see the hero state clearly.
  8. Check the result in the simulator before any firmware build or release.

Risks

  • Long event names can overflow the hero block. Use fixed widths and scrolling/ellipsis modes where needed.
  • LVGL calendar styling may not expose enough per-day control for a refined selected/today visual without deeper customization.
  • Auto-return should not fight user interaction while they are actively browsing dates.
  • The simulator validates layout, but hardware touch feel still requires device QA later.

Rollback Plan

  • Keep changes scoped to Page 1 UI logic so rollback is a single-file revert if the design feels worse.
  • Leave Bridge data contracts unchanged.
  • Do not include this in an OTA release until the simulator view feels right and a firmware build passes.

Implementation Result

  • Added a hero event block to Page 1 with status, title, and time/relative cue.
  • Changed event priority so active timed events win first, upcoming timed events win second, and all-day events are used as hero only when no timed event is available.
  • Rendered all-day items as quieter compact-list context when a timed hero exists.
  • Moved the remaining schedule into a compact list below the hero and kept transport pinned near the bottom of the right panel.
  • Reduced the top bar to a quieter single-row weather summary so the calendar hero remains the visual priority.
  • Compressed the transport section into two compact direction rows with route numbers, arrival times, and overflow counters.
  • Softened the calendar button matrix styling so the left panel is less visually dominant.
  • Added a stronger selected-day style and a quieter today highlight, so the active calendar day is easier to read without overpowering the hero event.
  • Added 5-minute auto-return from a selected non-today date back to today via esp_timer_get_time().
  • Removed the custom page dots and disabled the built-in tileview scrollbar to avoid duplicate navigation indicators.
  • Added simulator support for esp_timer_get_time() and fixture coverage for all-day events.
  • Removed a stale unused news buffer while cleaning compiler warnings.
