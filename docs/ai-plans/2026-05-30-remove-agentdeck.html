Remove AgentDeck Firmware Screen

Created: 2026-05-30. Scope: homedash ESP32 firmware.

Task Summary

Remove the fourth AgentDeck screen from the HomeDash firmware and remove the associated AgentDeck runtime logic. The firmware should return to a three-page dashboard: main dashboard, health/tasks/news, and Home Assistant controls.

Current Behavior

  • src/ui_dashboard.cpp includes ui_agentdeck.h and agentdeck.h.
  • The LVGL tileview creates four horizontal tiles and four page indicator dots.
  • Page 4 is created by ui_agentdeck_create(tile4).
  • A 2-second LVGL timer calls agentdeck_get_data() and ui_agentdeck_update().
  • src/main.cpp includes agentdeck.h, calls agentdeck_init() after WiFi/NTP, and calls agentdeck_poll() on every network loop.
  • src/agentdeck.cpp/.h implement mDNS/HTTP discovery, WebSocket connection, state parsing, and outgoing AgentDeck commands.
  • src/ui_agentdeck.cpp/.h implement the AgentDeck LVGL screen.
  • src/idf_component.yml adds esp_websocket_client and mdns dependencies only used by AgentDeck.

Desired Behavior

  • Only three tiles exist and swiping stops at the Home Assistant controls page.
  • Only three page indicator dots are rendered and updated.
  • No AgentDeck UI is created or refreshed.
  • No AgentDeck network discovery, WebSocket connection, reconnect polling, or command queue runs on the ESP32.
  • Build dependencies no longer include AgentDeck-only WebSocket/mDNS components unless another source file still needs them.
  • Dashboard data, calendar, lights, OTA, WiFi, NTP, and rollback behavior remain unchanged.

Approaches Considered

Approach Tradeoff Decision
Disable only the fourth screen Smallest UI diff, but AgentDeck network code and dependencies remain in firmware. Not enough for "всю его логику".
Remove screen and runtime calls, leave files present Build would stop using AgentDeck if includes are gone, but dead source files stay in the tree. Acceptable fallback if deletion conflicts with uncommitted work.
Remove screen, runtime calls, source files, and dependencies Largest but cleanest removal; requires careful build verification. Recommended.

Assumptions

  • AgentDeck is no longer needed anywhere in the firmware.
  • The existing three dashboard pages should keep their current layout and behavior.
  • The task does not require changing esp32-bridge; AgentDeck is local firmware/UI logic.
  • No physical flashing should happen without explicit confirmation.
  • The current uncommitted changes in CLAUDE.md, tools/gen_nvs.py, generated/managed component files, and file-mode changes must be preserved.

  • src/main.cpp: remove agentdeck.h, agentdeck_init(), and agentdeck_poll().
  • src/idf_component.yml: remove esp_websocket_client and mdns if no longer referenced.

Risks

  • The auto-generated src/CMakeLists.txt uses a recursive source glob, so leaving dead .cpp files in src can still compile them. Deletion or moving out of src is required for true removal.
  • Removing dependencies may require PlatformIO to refresh managed component metadata.
  • The working tree already contains unrelated uncommitted changes; implementation must avoid reverting them.
  • A build-only pass cannot prove touch/swipe behavior on hardware; final confidence needs device QA after OTA or USB flash.
